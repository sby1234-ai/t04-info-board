# 과제 4 제출 자료 — 오늘의 진짜 정보판 (데이터가 안 올 때)

## 제출 전 꼭 해야 할 일 (순서대로)

1. GitHub에 `t04-info-board`(또는 원하는 이름) 새 저장소 생성 → 이 폴더 전체 업로드(`.git` 폴더 제외).
2. **Settings → Actions → General → Workflow permissions** → "Read and write permissions" 선택 → Save.
3. **Settings → Pages** → Source: Deploy from a branch → `main` / `(root)` → Save.
4. **Actions 탭 → "Daily exchange-rate fetch" → Run workflow** 클릭 (1일차 실제 기록 생성).
5. 몇 분 뒤 Pages 링크(`https://sby1234-ai.github.io/<저장소이름>/`)를 열어 값이 보이는지 확인.
6. **다음 실제 날짜(KST)** 이후에 Actions 탭에서 다시 한번 "Run workflow" (또는 새벽 자동 실행을 기다림) → 2일차 기록 생성.
7. 2건이 모두 쌓인 뒤 아래 "제출물" 링크를 채워서 제출.

## 제출물

- **결과물 주소(무로그인 공개 심사 화면)**: `https://sby1234-ai.github.io/<저장소이름>/`
- **소스 주소(GitHub)**: `<저장소의 커밋 링크>`

## 짧은 확인 방법 (4줄)

1. **어디로 가나요**: 결과물 주소를 새 시크릿 창에서 엽니다. 로그인 화면 없이 바로 값이 보입니다.
2. **3단계 이내 무엇을 하나요**: ① 화면에 뜬 환율 값·단위·출처·시각을 확인한다 → ② 아래 "일별 기록" 표에서 서로 다른 두 날짜(KST)가 있는지 확인한다 → ③ 하단의 합성 실패 링크(예: `?sim=offline`)를 하나 눌러본다.
3. **무엇이 보이면 통과인가요**: 값·단위·출처·출처 시각·조회 시각·기준 시간대가 한 화면에 다 보이고, 어제 대비 변화값이 두 날짜 기록에서 계산된 대로 나오며, 합성 실패 링크를 누르면 그 실패에 맞는 안내와 "다시 시도" 버튼이 뜨고 직전 정상값은 "오래된 값" 표시와 함께 그대로 남아 있습니다.
4. **안 될 때 무엇이 보이나요**: 자동 조회가 그날 아직 실패했다면 화면에 실패 종류(느린 응답/401/403/호출 제한/오프라인/형식 변경)와 마지막 정상값·다음 행동이 표시되고, 절대 빈 화면이나 지워진 값으로 보이지 않습니다.

## AI와 나의 판단 (3줄, 초안 — 실제 확인한 내용에 맞게 수정해서 제출)

1. **AI에게 맡긴 일**: 정보판 코드(데이터 병합/중복제거/변화값 재계산 로직, GitHub Actions 자동화 스크립트, 합성 실패 화면 6종+복구 화면), 로컬 자동 테스트(로직 8건 + 화면 15건) 작성.
2. **학생이 직접 판단한 일**: 추적할 값(USD/KRW 환율)을 정했고, 저장소를 새로 만들지 기존에 합칠지 결정했으며, GitHub 저장소 설정(Actions 쓰기 권한, Pages 활성화)과 1·2일차 워크플로우 실행을 직접 하고 두 날짜 기록이 실제로 다른지 눈으로 확인했습니다.
3. **AI 제안을 따르지 않은 일(없으면 이유)**: 없음 / 있음 — 과제 카드가 요구한 공식 플랫폼 fixture(`assets/studio-task-assets/...`)를 이 세션에서 받을 방법을 몰라서, AI가 동등한 자체 fixture로 대체하자고 제안한 걸 그대로 받아들였습니다. (공식 fixture를 구할 수 있었다면 그걸 우선 썼을 것입니다.)

## 알려진 제약 — 정직하게 남겨둠

- 과제 카드 3에서 요구한 공식 플랫폼 자산(`README.md`, `public-contract.json`,
  `asset-manifest.json`, `T04-RECOVER-D2`)을 이 세션에서 내려받을 URL을 몰라
  확보하지 못했습니다. `fixtures/`의 6개 파일은 카드에 적힌 동작 사양(느린 응답/
  401/403/호출 제한/오프라인/형식 변경 + 복구)을 그대로 만족하도록 자체 제작한
  대체물입니다. `fixtures/README.md`에 이유와 교체 방법을 적어뒀습니다.
- 이 문서를 쓰는 시점에는 아직 실제 2일차 기록이 없습니다(자동화 장치만 준비된
  상태). 본인이 실제로 1·2일차 실행을 마친 뒤 "일별 기록" 표에 서로 다른 두
  KST 날짜가 있는 걸 직접 보고 제출해주세요.
